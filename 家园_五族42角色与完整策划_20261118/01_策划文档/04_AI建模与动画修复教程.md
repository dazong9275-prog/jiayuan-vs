# 《家园》五族人物多视图、完整体积与可动画模型修复教程

版本：2026-11-18 · 重设计执行稿 v1。用途：交给能够访问本地原工程、Blender、Unity 和目标安卓设备的 AI，逐角色执行并留下验证证据。

## 1. 本教程依据与真实状态

本轮读取了用户上传的《家园_最新人物结构与资产状态_20261117.md》以及对人物比例的最新要求。没有取得对应 `.blend`、`.glb`、贴图源文件或 Unity 工程，因此本文是一份有项目针对性的执行教程，不是已经修复真实模型的报告。文中的旧资产状态、面数与路径来自快照，执行 AI 需要打开文件再次核验。

项目现名为《家园》，五族为狼族、土拨鼠、狐狸、猫头鹰、獠牙黑猪。当前名单共 42 人：狼族 11、土拨鼠 10、狐狸 10、猫头鹰 10、黑猪 1。闻朔旧技术样板、旧女寨主、撤下的重卫和旧星轮杖主将不计入这份现行名单。

四个现有精修角色据快照均已有侧背精修，不能把它们统称为“一张正面平面”。真正需要检查的是：由单张图推断的后脑、胸背与四肢是否有合理体积，装备连接是否成立，武器和手是否粘连，衣服是否挡住关节运动，是否有合格骨架、动画和移动端表现。补画四视图、修网格、绑定动画和引擎验收是四件不同的事。

用户最新已授权重做全族人物、故事与机制。快照中记录的“暂停制作”“逐个人物批准”不构成本轮停止条件；应自主完成已授权工作，不额外制造批准流程。与此同时，不能把新补充的设计说成此前已确认，不能把历史取消项恢复为现行方案。

## 3. 阶段 A：清点、备份和分支诊断

### 3.1 建立不破坏原工程的工作区

1. 读取本地现行人物档案、GDD、资源清单与工程说明。以最新用户要求为准；记录与旧文档的差异，不删除原始依据。
2. 为每人建立独立工作目录，例如 `人物资料/狼族/双刀主将/动画就绪_v01/`。新源命名示例 `wolf_dualblade_animready_v01.blend`，原侧背精修文件保留。
3. 记录源文件 SHA-256、文件大小、修改时间、Blender 版本、单位、轴向、对象名、材质名、贴图路径、对象变换与修改器。存在骨架时，另记录骨骼层级、约束、顶点组、形态键、Action、NLA 与附件挂点。
4. 检查工作区现有未提交修改。保留 Unity `.meta` 与 GUID，不以删除资产目录、重新导入的方式“清理”引用。
5. 将缺失的贴图或外链列入问题表；取得并打开原文件之前，不勾选“已检查”。同一角色的美术 ID、运行 ID、旧路径与新路径全部记录。

### 3.2 Blender 固定诊断顺序

先保存原材质的正、背、左右和两个斜后方截图，随后在工作副本中诊断。

1. 检查对象类型、隐藏集合与可见性，确认人物由真实网格构成。检查面向相机的约束或脚本，以及是否只是 Plane、billboard 或极浅的浮雕。
2. 若实际存在骨架，在副本中比较 Rest Position 与当前姿态。静态摆姿模型没有可恢复的标准绑定姿态时，要先制作中性基础形体，不能凭空称它已有 A Pose。
3. 依次查看原材质、临时灰色不透明材质、Wireframe、Face Orientation。几何与贴图分开判断；临时材质放在检查副本，不覆盖生产材质。
4. 隔离头、身体、衣服、毛发与装备，从侧面检查后脑、胸背、胯、尾根和四肢。总面数很高仍可能只有薄壳，包围盒厚也可能来自一块错误背部凸起。
5. 在 Edit Mode 检查退化面、重复壳、内部垃圾面、异常孔洞与断裂边界。Non-Manifold 是诊断线索，不是自动修复命令。嘴部、衣领、袖口、头发卡片与被遮挡边界并不都需要封成水密实体。
6. 查看负缩放、Mirror、面朝向与背面剔除。只对方向已经确认的连续实体区域执行 `Mesh → Normals → Recalculate Outside`，常见快捷键为 `Shift+N`。开放衣片、毛发、镜像区单独判断，必要时局部 Flip。
7. 若灰模完整而原材质从背面消失，检查材质槽、Alpha、Shader、UV 岛、法线贴图和导出设置；不能先推倒重建网格。

### 3.3 按证据选择修复分支

| 观察结果 | 优先动作 | 不能这样宣布完成 |
|---|---|---|
| 只有二维 PNG，没有实际网格 | 完成多视图并制作完整体积；明确它目前是图像资产 | 生成背面图片后就写“3D 已修好” |
| 网格只有一层 Plane 或浅浮雕 | 重建头颅、躯干、四肢和服装体积 | 添加 Solidify 就当成完整人物 |
| 背面网格存在，但渲染中消失 | 检查面朝向、负缩放、材质与导出 | 对整个角色永久关闭剔除掩盖问题 |
| 后脑、衣服后片或肢体体积确实缺失 | 补几何与合理连接，随后重拓扑、UV、权重 | 镜像正面纹理当背面结构 |
| 网格完整但武器、手、衣服融合 | 根据运动关系切分并重建遮挡区域 | 只 Separate 对象却不恢复指节和握把 |
| 模型只是静态摆姿 | 制作可变形基础网格、骨架与动作 | 移动整个模型冒充行走动画 |

同一模型可以同时有多类问题。每修完一类，再做完整一圈检查；不能给四个模型套用一个未经验证的结论。

## 4. 阶段 B：把五族统一为狼参考的可爱比例

### 4.1 比例口径

以用户的靛蓝旗枪狼作为全族风格锚：大头、短颈、短腰、短粗四肢、圆润大爪与低重心，约三头身。测量时头高取解剖头顶至下颌，不把耳尖、帽子、毛簇计入；总高取同一头顶至脚底，不把旗杆、枪尖计入。约 2.8—3.2 个头高是绘制容差，不能为了数字生硬拉长脸或压扁身体。

黑猪的原图只继承男寨主身份、灰白毛领、石蓝衣、工程图、线坠和阔剑，不继承偏高的写实体型。狼、鼠、狐、鸮、猪应保留各自的口鼻、耳、尾、翼臂、爪与蹄形特征；不可将同一副真人身体仅替换头部。

不要对整件带装备成品直接做非等比缩放。先区分身体、衣服与刚性装备，在基础形体调整头、躯干与四肢；随后重新贴合服装、握把和挂点。已有绑定时保留原版，比例调整版重新检查静止姿态、权重与所有动作。

### 4.2 四视图的制作约定

每人至少有正面、背面、角色左侧与角色右侧四图，同一中性姿势、尺度、地面线和接近正交投影。把头顶、下颌、肩、肘、腰、膝、脚底水平线逐项对齐。侧面必须显示真实胸背厚度；背面必须给出后脑、后领、背带、腰带闭合、后衣片和尾根/翼根。

左右始终指角色本人：角色右手持物在正面图的画面左边，在背面图的画面右边。建立一张“非对称位置表”，包括单肩甲、辫子、面颊痕、耳缺、旧疤、箭袋、腰包和武器。四视图里任何换边都先修正，不能让建模 AI 猜一个平均结果。来源没有写清具体左右时，以实际最新认可图为证据；本轮新指定的位置标为新增设计。

宣传立绘的朝向与建模四视图分开。重弓手的宣传立绘保持 v08 右向、无头巾、无盾、大箭袋与骨角重弓；中性正视图必须正对镜头，不因制作四视图而把主立绘恢复成旧左向版本。医生的浅蓝头巾仍保留，重弓手取消头巾不适用于全族。

确认二维图的一致性后，先用同一个三维基础体块反向渲染四面进行覆盖对照。如果四张 AI 图不能对应同一个体积，先修参考或明确合理结构，不能将模型分别拉扯到四个互相矛盾的轮廓。生成的四视图属于概念参考，严格投影与细节接续要在建模阶段校正。

## 5. 阶段 C：拆开融合网格，建立能运动的结构

### 5.1 先按运动关系分类

身体和手是可变形网格；贴身衣服可随身体蒙皮；刀、枪、剑、十字架与经书主体通常为刚性部件；披风、旗、衣摆、尾巴和翼臂需要随动作设置控制。拆件是为了正确运动与维护，不要求最终把每片衣服变成单独 Renderer。

保留原高模作轮廓和贴图参考。先在副本制作简化的运动网格，确认姿态后再深化表面；不要直接在唯一精修高模上做不可逆切割。

### 5.2 武器与手融合时的具体步骤

1. 在 Edit Mode 用连通选择判断武器是否原本已独立。只有几何确实不相连时，才可用 `L` 选择部件、`P → Selection` 分离。
2. 若手和握把焊死，先沿握持接触边划定切割线，分出武器与手的工作网格；删除融合造成的错误桥接面，保留未损坏的外轮廓。
3. 重建被遮挡的掌面、拇指根、指节与握把圆周。至少保证手掌能张开、武器能从手中取出，不能在分离后留下一个贯穿手心的大洞。
4. 为刚性武器设清晰原点与握点，记录右手/左手或双手辅助握点。双手武器只由一个主挂点驱动，另一只手通过约束或 IK 对齐，避免两个父级同时拉扯同一武器。
5. 在中性姿势试装武器，检查掌指不穿握把；再做挥动、前刺与收回的低成本动作测试。静态好看的握姿不能代替运动可行性。

双刀要拆出两把刀并保留各自长度与轮廓。长枪要给枪杆、枪尖与羽饰合理运动关系，羽饰可用简化辅助骨或动画。阔剑要保持直刃收尖，不在拆件时换成斧、锤或其他武器。

### 5.3 服装、披风、背旗与尾巴

- 衣服若与四肢焊成一块，按贴身区和活动下摆区重新划分。肩、腋下、肘、裆、膝不能用长三角面横跨多个关节。长衣可保留前后开衩，为短腿大步幅留出空间。
- 先验证身体基础形体，再决定哪些遮挡内面可以删除。可见袖口、衣领和下摆需有合理厚度或内衬；不必为完全不可见处堆满细分。
- 披风固定点、旗杆支架与皮带是实际结构，不能靠正面贴图假装连接。旗杆主体保持刚性，布面单独变形，避免与背部共用错误权重。
- 狼狐尾巴从骨盆附近连接，有连续体积和根部权重过渡。粗尾可分若干控制段，数量按画面需求与设备预算决定；不要先给每簇毛都加骨骼。
- 大毛领、羽片和毛卡在肩转动时应跟随正确区域，禁止因自动权重把后领吸到手腕或把尾尖吸到脚部。

### 5.4 弓、箭袋、翼臂与坐骑

重弓应拆成弓体、弦和箭。定义握弓点、搭箭点和拉弦点；拉弦过程同时检查弓弦、手指和箭的方向。射出瞬间的可见箭与投射物显示应有一致交接，不能留一根永远粘在手上的箭。袋口、箭束与肩后至胯侧的挂带要有可读层次，抽箭不能穿越头部。

猫头鹰用翼臂与羽片结构表达握持。先搭肩—肘—腕的主要变形，再处理外缘羽片；不要为方便自动绑定直接改成人类裸手。教皇施法包含托书、举十字架、回收至待机的连续动作。

骑兵至少有骑手、山羊坐骑、鞍具与缰绳四类运动关系。骑手先完成站立四视图与独立基础动作，坐骑独立建模和绑定；再用鞍上挂点、双脚与手部约束组合。四张骑姿图不能替代被坐骑挡住的人体建模参考。骑手骨架与坐骑骨架分别命名、导出和验收，不能把二者焊成单个静态雕像。

## 6. 阶段 D：重拓扑、UV 与贴图

1. 用体块与极简绑定先证明姿态可行，再制作变形拓扑。肩、肘、髋、膝、手指、口鼻和翼根需要能支持实际动作的面流；主要关节保留足够环线，避免极长细三角跨关节。
2. 高模保留毛纹、针脚与铜件细节，运行网格只保留影响轮廓和近景的必要几何。不可仅为达到一个随意面数而破坏脸、耳、尾和武器的辨识度。
3. 当前 7.2—8.6 万三角面的旧模型是待优化输入，不是合格手机预算。先按目标设备、同屏人数、镜头距离、阴影与材质负担做实际测试，再确定 LOD 与贴图尺寸；不凭空给所有角色统一的“安全面数”。
4. 展开 UV 时保证可见背面、内衬和装备背面也有正确覆盖。非对称纹样、伤疤和有方向的文字不要无脑镜像共用 UV。接缝优先放在遮挡和自然结构处。
5. 烘焙前检查 cage、法线方向和硬边/UV 边界关系，测试手指、毛领、箭袋、旗架等相邻部件是否互相投射污染。必要时分组烘焙，但保持同一命名和材质对应。
6. 核对基础色、法线、粗糙度/金属度等通道。基础色与数据贴图的色彩空间按当前导出器和 Unity 渲染管线要求设置；通道打包规则写入导出说明，不仅用“有三张贴图”描述。
7. 逐个 LOD 检查轮廓、材质、骨骼兼容性、切换距离与跳变。减少贴图与材质时兼顾透明毛发的 overdraw，不把多重透明薄片当成免费细节。

## 7. 阶段 E：骨骼、权重与动作

### 7.1 骨架与绑定顺序

如果真实工程已有骨架或动作，先记录并保护它们；禁止直接删骨架、重新自动绑定、应用全部变换或应用全部修改器。拓扑改变可能使形态键失效，必须单独规划迁移或重建。

新静态角色先确定根节点、骨盆、躯干、颈头、四肢与附件骨架，再绑定身体与衣服。自动权重仅作起点，逐关节手动校正。刚性武器与道具使用骨挂点或完整刚性权重，不让刀刃跟手指一起弯曲。约束、驱动和控制骨不一定能被运行格式保留，导出前将必要动作烘焙到变形骨或项目约定的运行结构。

按实际项目选择 Generic 或 Humanoid，不假定动物翼臂与坐骑可以无损映射到标准人形。若要复用动作，先验证骨骼比例、轴向、静止姿态和触地，不直接把闻朔样板动作复制后宣布完成。

### 7.2 权重与极限姿态检查

逐个测试抬肩、肘弯、前刺、跨步、蹲身、转身、抬头与尾巴摆动。查看肩腋和髋部是否塌陷，护甲是否拉伸，衣服是否夹进体内，背旗是否穿过头部。翼臂举起时羽片保持连接，不出现破口和倒折。

权重应归一化；每顶点影响骨骼数与骨骼总量遵守项目实际平台设置。未使用的顶点组、约束与动作需确认后再清理，不在不了解用途时一键删除。

### 7.3 每个可出战角色的最低动作集

| 动作 | 需要检验的内容 |
|---|---|
| `idle` 待机 | 呼吸与重心自然；不滑脚；武器、尾与披风不持续互穿；循环首尾无跳变 |
| `walk` 行走 | 左右步节奏、脚掌接地、移动速度与步幅匹配；上下坡与转向不会把身体拖成长条 |
| `attack` 攻击 | 动作准备、命中时刻、收招完整；武器挂点正确；双手武器握点稳定；不能只转动整模型 |
| `hit` 受击 | 反应方向明确、不撕裂肩腰；与攻击/移动打断规则兼容 |
| `down` 倒地 | 身体与地面合理接触，装备不会飞到原点；倒地保持姿势与退场逻辑一致 |

再按职业补动作：双刀交替挥斩；旗枪前刺与举旗；重弓取箭、拉弦、放箭、收弓；寨主双手挥剑与工程互动；教皇托书举十字架施法；医生包扎或提灯；炼金师投放/使用药剂；骑兵上鞍姿态、骑乘循环与坐骑步态。具体游戏只需哪些动作，由已确定机制清单决定，不为未立项系统无限扩展。

动作事件标记与游戏伤害结算分开。动画回调不能成为重复领奖或多次扣血的唯一依据；快放、跳过演出、存档恢复都要保持同一规则结果。根运动或原地动画采用项目统一方案，不能有的角色由导航移动、有的角色又被根运动多移动一次。

## 8. 阶段 F：导出并在 Unity 中真实检查

1. 记录使用的 Blender、导出器、Unity、渲染管线与 GLB 导入包版本。Unity 是否支持当前 GLB 由工程实际包决定，不假定任何新项目都能原生导入它。需要改用项目已有格式时，保留原源与映射说明。
2. 使用项目现有导出预设核对单位、前向/上向轴、比例、骨架、材质、贴图路径与动画片段。先导出一个测试角色，验证后再批量。
3. 把运行资源放入与当前工程约定相容的目录，保留原 `.meta`/GUID 或通过明确迁移维护引用。美术 ID 与运行 ID 保持映射，不能因为文件更名就创建第二个同名人物。
4. 打开实际战术场景，使用真实摄像机、光照、阴影、材质与后处理。检查正、背、左右、斜后视角；在 Blender 看起来正确并不等于游戏正确。
5. 检查 Animator、Avatar/骨架映射、骨挂点、角色控制器/碰撞体、武器位置、角色比例与地面接触。动画播放时检查 Renderer bounds，避免抬手或举旗后被错误裁剪。
6. 在项目目标渲染管线下核对透明模式、剔除、法线贴图方向、阴影与批处理条件。合理薄片可以按规范使用双面材质；身体完整性仍要用单面不透明检查材质复验。
7. 依次验证待机、移动、转向、攻击、受击、倒地及职业特殊动作，留下场景名、资产版本和录屏。编辑器许可证、导入器或构建环境缺失时，将阶段登记为“阻塞/未验证”，不能写成已通过。

## 9. 阶段 G：安卓与交付验收

以目标手机或项目明确的低端/中端设备档位实测。记录设备型号、分辨率、画质、同屏单位数、帧时间、内存、Draw Call、三角面、透明 overdraw、骨骼与阴影成本。稳定 30 FPS 可以作为首轮设计目标，但未实测前不是结论。

测试包含近景四方向审看、真实战术视角、同屏队伍与敌人同时行动、长时间场景切换、切后台恢复。移动端不能只用桌面编辑器帧率替代证据。优化先定位瓶颈，再调整 LOD、材质、阴影、贴图或骨骼复杂度；不要盲目降低面数而留下真正的透明与材质负担。

最终四向截图、后侧截图和 360° 转台必须从同一个最终模型渲染。严禁用不同生成图片拼接冒充网格验证。保持相机距离、光照和背景一致，并保留灰模检查版本以便看出实际体积。

### 分阶段状态，不用一个“完成”覆盖全部

| 阶段 | 交付物 | 通过条件 |
|---|---|---|
| A 资料与诊断 | 文件清单、源哈希、问题表、修改前截图 | 实际文件可定位；问题有证据；原件有保留 |
| B 设计与比例 | 四视图、左右表、关键部件图 | 约三头身风格一致；同角色各视图可对应；新增设计已标记 |
| C 体积与拆件 | 完整体积工作模型、运动部件表 | 背部和侧面合理；武器手衣服不再阻碍所需动作 |
| D 运行网格与贴图 | 拓扑、UV、烘焙图、LOD 候选 | 轮廓与细节符合设计；无明显烘焙污染；预算有依据 |
| E 绑定与动作 | 骨架、权重、基础与职业动作 | 规定动作无明显破面、滑步、错误拉伸和穿插 |
| F Unity | 场景、导入说明、动作与四向录屏 | 真实工程引用正常；渲染、控制和动作一致 |
| G 安卓交付 | 设备测试报告、最终源/导出/转台 | 目标设备达到项目标准；文件可重新打开与复现 |

每项状态使用“未检查 / 进行中 / 待修订 / 通过 / 阻塞 / 不适用”，并写证据路径。当前本轮二维概念图至多支持 B 阶段的一部分，不能自动将 C—G 标为通过。

每人最终目录应包括：角色档案、原始依据、最新四视图、可编辑 Blender 源、运行导出、贴图、骨架动作、同一模型转台、Unity 验证、安卓记录、变更说明和已知问题。图片源没有图层时如实称 PNG，不虚构 PSD 源稿。

## 11. 最后检查清单

- 42 个现行人物均有独立 ID 与记录，历史样板和撤下造型没有混入正式名单。
- 五族比例统一但身份不同；普通职业不只是主将换武器；左右方位和后背结构能够解释。
- 身体、装备、衣服与道具的体积真实存在，合理薄片材质未掩盖身体缺面。
- 同一最终模型在正、背、侧、斜后均可审看；动作集与引擎表现分别有证据。
- 文件路径、贴图、动画、GUID 引用和别名映射正确，源文件可重新打开。
- 没有把文档旧记录、AI出图、整模型移动或桌面预览写成安卓正式角色交付。

完成标准是能复现的文件与表现，而不是一张好看的正面截图。
