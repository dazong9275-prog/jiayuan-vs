# 性能预算、资源打包与引擎导入

参考目标为Unity URP的PC与移动两个质量档。用户尚未指定设备型号，以下是内容规划起点，不是已测帧率承诺。没有完成模型、引擎集成或Profiler采样之前，交付清单不得标记“手机稳定60帧”。

## 1. 整图预算先于单件上限

| 项目 | PC起始目标 | 移动起始目标 | 统计范围 |
|---|---:|---:|---|
| 主镜头可见静态三角 | 150k–300k | 80k–150k | 地面、建筑、机关、背景；角色/特效另记 |
| 场景纹理驻留 | 128MiB | 64MiB | 当前mip与压缩格式实际占用，角色另记 |
| 同屏投影实时主灯 | 1 | 1 | 小灯优先烘焙/无阴影 |
| 静态材质规划 | 4区域共享＋2机关＋1水/透明起步 | 尽量合并到4–6共享组 | 不是DrawCall保证 |
| 透明重叠 | 主棋盘同像素尽量≤2层 | 尽量≤1层 | 水、草、雾和粒子必须一起检查 |

每张图做预算表：模块类型×可见实例数×当前LOD三角数，汇总地面/结构/机关/植物/背景五类。加上角色、阴影、粒子、UI与后处理后才是整帧成本，不能拿静态网格预算当游戏总预算。

例如一张图81块地面×400=32400三角，20组岩壁×1500=30000，6个机关×3500=21000，生活物和植被约18000、建筑和背景约70000，共171400。这个估计仍需检视相机裁剪、阴影额外绘制与透明成本；数字适中不等于已经优化。

## 2. 贴图内存怎么算

2048×2048纹理采用8bit/像素块压缩（如BC7/部分ASTC配置），含完整mip链约5.33MiB；未压缩RGBA8含mip约21.33MiB。1024在相同格式下约为其四分之一。法线、通道图各自单独计，不要把“一套2K贴图”误记成“一张2K”。

若4个共享材质每个有BaseColor/Normal/打包通道3张2K、每张约5.33MiB，已约64MiB，再加机关、水、光照图和其他资源会超过移动目标。移动档应降低部分纹理到1K、复用材质或使用更合适压缩；不能只降低屏幕分辨率。

颜色图用sRGB；法线和数值通道使用线性采样。压缩格式按平台支持选择，透明边和法线需看压缩瑕疵。保留未经通道打包的工作源，导入步骤负责转换，避免后来无法还原粗糙图。

## 3. LOD和剔除

普通模块可从LOD0→约50%→约25%三角起步，具体看轮廓而非机械减面。机关手柄、读数牌和状态图形优先保留；最后一级仍必须看得出开关态。小物可在足够远时剔除，不能把胜利交互点也剔除。

LOD距离按屏幕占比校准，地图正交镜头缩放也要触发正确变化。每级pivot与bounds一致，无跳位；碰撞代理独立于视觉LOD。远景阴影可关闭，主棋盘接触阴影保留。草簇先减透明重叠再减三角，洞穴先剔除被顶壳挡住的外部远景。

## 4. 源资源目录和命名

```text
MapArt/{mapId}/
  Source/               // .blend源与导出预设
  Meshes/               // .fbx或.glb，选一种主交换格式
  Textures/             // BaseColor/Normal/Roughness等
  Materials/            // 引擎材质或绑定说明
  Prefabs/              // 有Unity执行环境时交付
  Review/               // 四向截图、状态对照、报告
  Manifest.md           // ID、尺寸、版本、来源、限制
SharedEnvironment/{biomeId}/...
```

例：`ENV_BI05_SnowRock_A_LOD0`、`P17_ValveA_Handle`、`T_BI05_Ground_BaseColor_2K`。一个文件不要叫“final_final2”；版本写manifest和文件修订号。外部素材记录来源及许可，生成资产记录任务和工具版本，便于重复制作。此结构是未来资产目录，当前MD包不附假模型文件。

## 5. Blender到Unity的参考步骤

1. 建模以米设置，尺寸和pivot按规范；应用缩放，清理负缩放与重复面，确认低模、LOD和碰撞代理命名。
2. 只导出选定资产，保留源文件；选择固定FBX或glTF预设并记录轴转换选项。先用A1/B1/A2轴向代理验证，避免手动再旋转一次。
3. 导入Unity测试场，检查1.5m格宽、正面方向、正常缩放；Normal贴图类型正确，粗糙转Smoothness一次，透明模式与渲染队列明确。
4. 建Prefab：Root、Visual、StateParts、SelectionProxy分离；将碰撞代理放到指定层，不自动给所有网格生成MeshCollider。
5. 按objectId绑定状态材质/动画，关闭动画事件中的逻辑回调；用保存状态直接恢复最终姿态。
6. 使用场景的逻辑格生成定位，摆放批准实例；装饰不写入导航或战斗数据。
7. 建四向相机、灰阶/低特效测试配置，逐项完成验收。确认无逻辑变化后再优化图集、合批与LOD。

FBX不保证把DCC中的程序材质完整传给引擎，须烘焙批准的纹理。glTF材质语义也需对照实际shader。两个格式不要在同一资产反复往返覆盖源文件，否则容易改变坐标、切线与材质数值。

## 6. 剖析与降级顺序

使用引擎Profiler、Frame Debugger和平台GPU工具确认瓶颈来自CPU提交、阴影、透明填充、纹理还是网格。保留同一相机、同一机关状态和同一单位数量比较，不以两个不同场景截图判定优化成功。

- CPU批次高：先统一材质/子网格，检查重复材质实例；SRP Batcher只降低部分CPU成本，不等于合成一次绘制。
- GPU阴影高：减少装饰投影、缩短影距、降低阴影分辨率，保留单位与关键建筑接触关系。
- 透明高：稀疏草、改Alpha Clip、削减雾层、水面用更简单shader；保护格标记清楚可见。
- 显存高：减少驻留mip、改压缩和共享图集，优先保护机关标记分辨率。
- 网格高：按屏幕占比降LOD和剔除后景，先保主轮廓与关键状态部件。

每次优化记录前后采样环境和画质损失。若尚无目标设备，只写估算、待测项和可降级策略，不编造毫秒与帧率。
