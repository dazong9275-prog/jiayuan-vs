# 统一尺度、棋盘空间与场景结构

本规范与[制作约定](制作约定.md)及逐图工作单共同使用。目标是让AI产物能组成可旋转查看、有厚度、清楚且有生活感的战棋场景。当前只提供指导，所有网格和场景均待制作。

## 1. 先锁定逻辑边界

玩法图决定可走、遮挡、步耗、出生、目标与机关。美术人员先从对应玩法MD提取下表，不允许边画边改变路线。

| 字段 | 要记录什么 | 不可自动推导的内容 |
|---|---|---|
| Cell | 列、行、地形、层高、步耗 | 漂亮的坡道不能自动产生通路 |
| Object | objectId、目标格、是否占格、交互邻格 | 大阀模型不自动变成障碍 |
| State | 初态、成功、失败、复位、锁定 | 看起来已打开不等于逻辑已通过 |
| Bounds | 可玩格包围盒、不可走外圈、视觉外延 | 远景小路不默认可点选 |
| Sight | 墙、矮障、雾、掩体规则 | 模型半透明不取消逻辑遮线 |

逐图工作单中的新地标、草、岩面、小房和生活道具均为视觉建议；只有原玩法图明确占格的对象才允许建立相应逻辑阻挡。发现原对象不够放下时，缩小或外置视觉本体，并以指示杆/地下管连接目标格，不移动逻辑坐标。

## 2. 一格与世界坐标

统一1格=1.50m。A1格中心为引擎坐标(0,0,0)，X向东、Y向上、Z向北，行号增大朝南。

`X=1.5×(列序号−1)`；`Z=−1.5×(行号−1)`；`Y=玩法层高`。列A序号1、B为2。D4中心=(4.5,0,−4.5)。无明确玩法层高时，所有可走顶面Y=0。

| 图规格 | 中心点范围X/Z | 包围盒外沿 | 总宽×深 |
|---|---|---|---|
| 9×9剧情P01–16 | X0…12；Z−12…0 | X−0.75…12.75；Z−12.75…0.75 | 13.5×13.5m |
| 11×9剧情P17–32 | X0…15；Z−12…0 | X−0.75…15.75；Z−12.75…0.75 | 16.5×13.5m |
| 9×7竞技A01–08 | X0…12；Z−9…0 | X−0.75…12.75；Z−9.75…0.75 | 13.5×10.5m |

尺寸含外框格，不能把外框墙当作新增一圈免费通路。视觉外延在包围盒外另做：近景延伸2–4m用于收边，远景山谷10–30m用于构图。远景不得挂入拾取、移动或战斗射线系统。

模块地面顶面0，底面−0.20m。允许0.03m内的浅起伏用于表现地表，角色脚点仍以规则地面为准；石阶、沟坎、积雪堆和堤岸的大起伏只能放在已不可走格或棋盘外。浅水格采用下凹床面和水面覆盖表现，不把既有Y=0站立脚点变成游泳深度。

## 3. 角色和道具的尺度参照

普通棋子站立视觉参考高1.10m、肩宽约0.75m，不含耳、角、武器。实际八族体型以角色规格为准。测试代理只需显示此包围体；不是新增角色建模任务。巨体逻辑足迹3×3m，不能拿普通角色放大后挤进单格过道。

| 元件 | 初始尺寸建议 | 设置理由 |
|---|---|---|
| 单格地模块 | 1.50×1.50×0.20m | 边缘连续、不会悬空薄片 |
| 路沿/收边条 | 长1.50，宽0.12–0.25，高0.08–0.18m | 沿不可走边摆，保留清楚通路 |
| 小木箱 | 0.35–0.60m边长 | 非占格剧情工具不得放中心挡脚 |
| 阀柄 | 直径0.25–0.40m，轮缘厚0.04–0.07m | 俯视有轮廓，避免纸片圈 |
| 状态铭牌 | 宽0.35–0.55，高0.20–0.30m | 颜色加形状；文字由UI生成 |
| 栏杆/矮掩体 | 高0.55–0.80m | 仅在原格图有对应类别时使用 |
| 高墙/房壳 | 高1.8–3.0m | 需要视觉剖切组，不扩大逻辑遮挡 |
| 后景树木 | 高3–6m，冠径2–5m | 只在不遮棋盘的外缘放大体积 |

非占格机关在格心做厚0.04m以内的嵌地标记，本体侧置或外置；人物能同格站立时，所有姿态不得穿进机关实体。不能用碰撞禁用来掩饰明显的视觉穿模。

## 4. 场景层级

```text
SCN_Pxx_MapRoot          // 位置0、旋转0、缩放1
  LogicAnchors          // 引擎权威锚点，建模AI只读
  GroundVisual          // 可走面、收边、水面
  StructureVisual       // 洞壁、房壳、不可走岩体
  InteractiveVisual     // 每个objectId的状态部件
  OcclusionVisual       // 可淡出前墙、屋顶、洞顶
  StoryDressing         // 生活物和植物，无玩法碰撞
  BackgroundVisual      // 不可进入山谷、湖岸、天空
  CollisionProxy        // 与装饰分离的批准代理
  LightingAndVFX        // 灯光、雾、雪、火花
  ReviewCameras         // 固定四向、近景与全图相机
```

地图物件采用`P17_VALVE_A_Visual`这类稳定语义ID；可共享的模块用`ENV_COMMON_Floor_150_A`，实例名再带格坐标。每个移动部件单独对象，命名`Root/Base/Handle/Needle/StateLamp`，不要把转轴与静态管网焊成一个网格。

## 5. 模块拼接

主对齐栅格1.50m，辅助构造栅格0.25m。模块pivot为底面中心；跨格长件中心和尺寸明确，桥的旋转pivot使用真实铰链，挂在对齐底座之下。所有重复模块先在2×2和3×1样板中检查接缝，确认边界顶点一致，再做美术变化。

地面每生态至少3种：安静主面A、边缘磨损B、局部生活痕C。变化发生在表面分布与细节，不改变边界高度。大岩体需要一段中间件、两个端头和转角件，不能靠镜像负缩放造成法线或纹理方向错乱。禁止每格都用同样大小的孤立方砖，除非该地本来就是人工铺地。

## 6. 四向可读的构图

首个镜头为正交，相机俯角55°（相对水平面），从棋盘南侧偏25°观察；这是参考起点，最终以四向读图决定。围绕棋盘中心转90°形成四个审查角。摄像机正交尺寸应将棋盘四角投影后自动包住，额外留15%边距；不要固定一个尺寸导致宽图被裁切。

每图只选一个主地标和两个次地标。主地标落在已封闭地块或远景，左右大小与轮廓不同以保留非对称特色。中心战斗区留足安静表面，边缘有高差与世界延伸。相机转动后所有必要阀柄、门状态和进度格仍可读；挡住时淡出Visual，保留地面标识和逻辑遮挡。

## 7. 轴向与导出自检

Blender使用米、Z向上；引擎Y向上。由导出/导入工具完成一次轴转换，不再手动把模型旋转90°补第二次。先导出三块带文字标识的A1/B1/A2代理：导入后A1=(0,0,0)、B1=(1.5,0,0)、A2=(0,0,−1.5)，再批准整套配置。不同FBX/glTF版本不能仅凭“常用参数”猜方向。

导出对象应用缩放、禁止负缩放、pivot正确，记录软件版本与导出预设。根节点最终旋转0、缩放1，若导入器产生转换父节点，应封装并记录，不能由关卡搭建者逐件纠正。原始场景和交换文件都保留；后续返工从源文件继续。
