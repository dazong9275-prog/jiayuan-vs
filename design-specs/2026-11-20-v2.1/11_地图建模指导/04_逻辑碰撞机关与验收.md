# 逻辑、碰撞、机关状态与验收

这是未来模型的验收工作单；本轮没有执行引擎渲染或模型导入。使用时每一项需附对应资产ID、截图/录像或检查记录，不能由生成AI一句“已满足”代替。

## 1. 三种几何必须分离

`VisualMesh`供观看，`PhysicsProxy`供需要的点选/表现碰撞，`BoardLogic`保存可走、遮视线、掩体和机关规则。三者不能互相自动覆盖。装饰模型带BoxCollider不等于新增战斗障碍；任务交互格也不应因为渲染模型有空洞而无法点击。

每个对象有`visualId`、`logicObjectId或null`、`occupancyRole`、`selectionProxy`、`occlusionGroup`。VisualOnly对象的战斗碰撞关闭，若需要相机避障使用独立层。路径和攻击射线读取逻辑棋盘，点击选择通过批准代理映射到同一个logicObjectId。

## 2. 机关状态表模板

| 字段 | 实例要求 |
|---|---|
| 对象 | 原玩法表的ID、格坐标、交互位置 |
| 初态 | 真实状态值，例如阀0、屏风竖起、桥落位A |
| 变动部件 | 哪个网格绕哪个轴、移动多少米或转多少度 |
| 成功 | 明确锁存/灯形/指针位置，不只改变颜色 |
| 错误 | 正常读数仍保留，错误提示不生成伤害或拆除 |
| 复位 | 哪些部件回初值、哪些已完成阶段保持 |
| 占格与遮挡 | 对应逻辑状态；视觉剖切不能改变它 |
| 保存与加载 | 直接恢复最终姿态，不补播发奖/开门事件 |

模型可以预留动画片段`idle/switch/accepted/rejected/reset`，但逻辑状态变更只能来自已确认的权威事件。动画中段不临时允许角色穿门，播放两次也不能重复触发完成。中途读档时按保存状态直接放到正确位置，不能因动画尚未完成而重新执行机关。

## 3. 不占格机关如何有实体感

优先四种方式：①嵌地阀盘，高度≤0.04m；②放在原墙体侧面，交互点留在批准邻格；③大型机体放棋盘外，导管/指示杆连到目标格；④让目标格显示立体投影/刻度，实体控制台置于原不可走格。

选择后仍用普通人物站姿、受击、交互和巨体足迹检查。若人物站在该格会穿控制台，必须移动视觉本体或修改显示形式，不能擅自把该格改不可走。远景动作不得被玩家误读为新桥或可乘货台。

## 4. 洞顶和房屋剖切

洞穴至少分地面、后壁、前壁、侧壁、顶壳、切口封边六类。前壁/顶壳可按相机遮挡淡出，切口要有岩层厚度，不出现空心纸壳。屋顶同理，拆独立屋檐和墙头收边。相机进入另一个方向时使用同一规则，不靠只对初始视角特制的洞口。

淡出只影响Visual，逻辑实墙仍不可走且仍阻挡视线。选中墙后敌人也不能借剖切获得非法攻击。地面图标、任务读数和必要交互提示使用不被淡出壳遮挡的显示层，同时保持玩家可读的遮挡原因。

## 5. 逐图必做的视角组

| 视角/状态 | 检查什么 | 直接退回的情况 |
|---|---|---|
| 顶视无透视 | 格图、尺寸、对象锚点 | 任何格数、门格或出生位置被美术改动 |
| 55°初始与90°三次转向 | 关键牌、角色、走道和整体特色 | 只能一个方向看见机关或背面缺失 |
| 最近允许缩放 | 接缝、像素密度、穿模与法线 | 明显黑缝、悬空、重复Z-fighting |
| 最远允许缩放与720p | 单位/可走面/危险边界 | 必需信息只剩难辨色点 |
| 机关全部合法状态 | 动件支撑、门桥遮挡与复位 | 状态恢复不到同一最终姿态 |
| 巨体与三名角色相邻 | 足迹、标记、视觉拥挤 | 装饰把合法格伪装成不可站 |
| 无粒子/无音效/灰阶 | 必需线索独立存在 | 解谜只依赖颜色、闪光或声音 |
| 竞技两程 | 两队出生视角、核心/终点 | 交换后标识错方或一方被装饰遮挡 |

## 6. 静态网格与材质检查

- 实体部件完整侧背、无意外单面孔洞、法线一致；薄面用途有名单。
- Transform尺寸和pivot正确，无负缩放，整图根缩放1。
- UV0无非预期拉伸；UV1无重叠；贴图命名和色彩空间正确。
- 桥底、石壁基脚、房檐有厚度；浮动物、绳端和管线都有连接解释。
- 没有拼缝透光、重复共面、穿透角色站位或跨出禁止边界的模型。
- LOD切换不移动pivot、不丢必要机关状态牌；交互代理不随LOD消失。

自动检查脚本可检测非流形边、负缩放、丢贴图、超预算、碰撞层等；艺术构图、可读性和逻辑一致性仍要人工审查。为薄面白名单保留例外，不能把所有开放边误判为坏模型。


坐标错、背面缺失、状态错或新逻辑阻挡属于阻断问题；先修再交付。远景细节不足可排后续，但不得把“先交付”写成已完成全部质量验收。
