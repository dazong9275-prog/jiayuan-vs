# 存档、联网、重连与结算

本文件规定上线前应具备的行为和失败处理。它不代表服务已部署。玩法参数引用[统一规则](../00_统一规则_先读.md)。

## 帐户数据分区

| 分区 | 保存内容 | 更新来源 |
|---|---|---|
| Profile | 用户ID、显示名、设置、语言 | 账户服务 |
| CharacterRoster | 角色解锁、职业训练、外观引用 | 经账本登记的剧情事件或训练修改 |
| LoadoutPresets | 自取配装名、角色ID、职业、10点训练分配、8槽装备、技能ID | 营地配装服务，保存前通过LoadoutValidator |
| WorldProgress | 已完成P01–P08、钥匙、区域节点开放、个人故事选择 | 关卡权威完成条件与选择命令 |
| ItemUnlocks | B/S装备图纸、领取状态、工坊池开放 | 幂等奖励事务 |
| CampaignCheckpoint | 地图内容版本、检查点、战斗快照、任务物持有 | 离线战役或受控存档点 |
| CompetitiveRecord | 赛季、段位、对局结果、模式分离统计 | 服务端结算 |

竞技采用同级借用库。竞技配装由玩家选择ID，房间用当前contentVersion从库里还原固定参数。客户端不得把自己战役存档中的hp、攻击、药品数量直接提交为竞技面板。

## 关卡奖励的幂等事务

每次进入关卡创建RunId，首次奖励以 `AccountId + RewardKey` 唯一，`RewardKey`包含关卡ID与奖励类型，例如P04主线钥匙、P04工坊池、P04支路首件。每场结果另以 `AccountId + RunId + SettlementVersion` 唯一，防止同一完成事件重复记账。

一次事务顺序为锁定当前结算行→验证关卡完成及检查点版本→写入首次奖励账本→授予钥匙/图纸/开放池→写入关卡进展→标记本Run已结算→提交。任何数据库步骤失败整笔回滚，重试使用同一个RunId；无法确定网络结果时先查账本，不创建新Run再次领奖。

同一关重复游玩不重发已领取的首通奖。选择型奖励提交选择ID并保存；重发同一选择返回原结果，换成另一选择返回Conflict并显示已选项。玩家在角色死亡、退出应用或断网后不会失去已登记的主线钥匙。

## 保存与读取

离线战役在每次逻辑命令提交完成后可记录事件日志，在关卡规定检查点写完整快照。写本地快照采用临时文件→内容校验→原子替换，保留上一份有效快照。快照包含contentHash与schemaVersion，不依赖Unity对象序列化文件。

对于云存档使用服务器revision和设备checkpointId。旧设备上传时发现revision落后，需要比较当前关卡进展并由用户选择可恢复的检查点；解锁账本取服务端已确认集合，不能通过覆盖旧整档删除已领物或再次领取。竞技记录只读服务端结果。

回到检查点会回到当时地物、单位和目标状态。既有首通奖励只在通关事务中发放，检查点快照中记录已登记奖的引用，读取快照不会调用授奖函数。

## 联网请求与广播

房间服务建立一场对局后分配MatchId、四个UnitId与玩家控制关系。双方确认mapId、内容哈希和配置锁定；哈希不一致不能开始。可靠有序传输可选WebSocket，命令以JSON或二进制协议序列化，首版优先可调试和可追踪。

客户端提交commandId与expectedStateRevision。重复commandId返回原CommandResult；同ID不同内容直接拒绝。比当前版本落后的合法请求返回StaleState与缺失事件或最新快照，客户端刷新预览。未来版本号或无权限actorUnitId拒绝并记录。

服务端广播每批事件的起止sequence、状态revision、最终stateHash、下一激活者与服务器deadline。客户端动画可以快速跳过，deadline在权威结算后按同一规则启动。两台机器不能各自用动画结束时间开始25秒计时。

核心结果在可信服务器计算。客户端可以用同版内核做预览，但正式扣血、移动落格、消耗品、复归和胜负均服从服务端。每份命令记录来源玩家、当时激活者和校验结果，便于排查错误指令或异常频率。

## 超时、断线与双人配合

每激活25秒，每队每程一次20秒延时。延时由当前行动者请求，服务端检查尚未用过再延长deadline并广播给双方。到时先按规则结算未完成的起手选择（默认正常爆发），再对尚未提交的剩余AP执行至多一次默认架盾；已架盾或AP不足则直接结束；已接受且正在结算的命令完整结束后再推进，不得同时出现玩家攻击与系统架盾抢扣同一AP。

断线窗口最多60秒，对局计时仍按统一规则继续。窗口内原玩家用同一凭证可重连恢复自己的棋子；超过窗口按整场弃权流程结算一次。2v2队友不能自动接管掉线者的棋子，防止临时共享控制造成责任不清。待机默认行为和复归规则保证断线时状态有唯一答案。

药品与核心的交接属于需接收方同意的动作。在施方激活中先发送不扣费的Offer请求，目标玩家可在短窗口内接受。接受只代表意愿；执行时重新检查距离、库存、行动者、AP和当前revision，满足才原子扣费并转移。拒收、过期、移动后不满足均不扣费。单排玩家控制双方时，UI直接用本人的二次确认完成接受，仍走相同服务器校验。2v2预画路径与标点仅是队内信号，不改变棋盘状态。

## 重连协议

客户端报告lastEventSequence和stateHash。服务端若保留之后事件且哈希对应，发增量；否则发当前完整快照及当前sequence，客户端清空旧未确认预览后重建。重放已确认的commandId只收原回执，不重新施法。断线重连时当前精力、冷却、消耗瓶、形态次数和本轮反应次数全部来自快照。

复归用地图定义的候选格优先序找合法足迹，选中后由规则建立单位。不能在客户端自行找一个“看起来没人的地方”。候选格全阻挡时本次复归激活结束，状态仍为待复归，下次本单位激活再试。连通性与复归拥堵需要在地图验收中覆盖。

## 回放与内容版本

回放保存开局完整快照、已接受命令、有序结果事件、每激活最终状态哈希、内容哈希和内核规则版本。每个激活可有一个索引快照用于快进。回放不能只存模型位置与视频帧，需能复现费用、地物、伤害和胜负。

补丁上线时，进行中的房间继续锁定旧contentVersion。新匹配切到新版本。保留旧版本数据和可用内核兼容范围供回放验证；不兼容旧算法时至少保留原事件结果播放，不把旧指令送进新算法重算后假装原战况。

存档迁移按schemaVersion逐级进行，有迁移前备份、迁移报告和回滚入口。移除装备ID时，通过内容墓碑表映射到合法保留项或待用户重配状态；已拥有图鉴记录保留。若一套配装新版本不合法，营地列出准确冲突，竞技开始前要求修正，不在开战中静默删一个技能。

## 结算恢复场景

| 失败点 | 应恢复的结果 |
|---|---|
| 客户端提交交灯后断线，服务端已经接收 | 权威命令照常结算，重连返回同commandId的胜负事件 |
| 数据库已授奖但响应丢失 | 客户端重发同RunId，返回原奖励结果，不新增账本行 |
| 房间进程退出 | 从最近快照加持久事件恢复，核对状态哈希后继续；恢复无法验证时取消竞技结果并记录异常，不能任意判一方胜 |
| 两个设备同时改配装 | revision更早者先成功，后者收到冲突并刷新；已锁定对局不受营地改装影响 |
| 版本升级时玩家停在机关中间 | 使用旧地图内容完成/恢复该次Run，或通过显式迁移退回最近合法检查点；不把角色放进新墙中 |
