# 实现切片、任务依赖与交付验收

目标是逐步证明《家园》的深层组合、关卡解谜和对战可行，再铺开300件装备与完整美术。本文件是实施路线，不代表已有程序、服务器或性能测试结果。每个切片都保留纯逻辑回放，避免先堆资源后发现规则无法成立。

## 团队职责与交付形状

策划负责确定条目参数、关卡证据路线和批准卡面；程序负责相同输入产生相同结果、联机权限及持久化；美术负责轮廓、动作、特效和场景可读；测试负责复现初态、步骤、实际/预期结果。小团队可以一人兼任多个职责，发布规则仍需有另一轮独立检查。

每次切片交付包含可运行构建、锁定内容哈希、已启用ID清单、操作说明、验收记录、已知问题、至少一份正常回放和一份失败输入回放。本设计包本身只含MD，不用空工程或截图冒充这些后续产物。

## 切片一：无美术也能下完一轮

范围：纯C#内核、方格测试场、4枚棋、2AP/精力/冷却、步行、普攻、架盾、顺序轮转。先不接账号或外部数据库，不要求模型。实现对象ID与状态版本，从第一天记录命令和事件。

验收门槛：同一初态加相同20条命令在客户端目标运行时与服务端目标运行时得到一致最终哈希；输入非法落点、旧revision、重复commandId、AP不足均无部分扣费。一次激活不能步行两次或主动伤害两次；剩余AP不会带入下一激活。CD1在使用后的下一次自身激活不可用，再下一次可用。交付逐条断言报告，不能只提供“运行没报错”。

## 切片二：一个真实谜题和一个组合发现

范围：采用P01中经策划批准的最小遭遇，保留其真实坐标、机关与目标；若简化图须用DEV前缀而不覆盖P01正式规格。启用木、铜、水、压力板、轨道、固定状态，以及至少一个推物操作与一个电标签操作。启用一把普通主手、一件转换装备、一件地物装备、一项防护反应和巨化验证。

验收门槛：普通装备配置能够通关；另一种跨职配置能用同样物性获得不同但合法的解法。开发者能指出每步对应的局部规则，不存在按配装ID列表检测的隐藏奖励。巨化四格非法时不扣费，同招扫到四格仍只伤一次，变形结束HP不变。两个不同机关对象使用相同标签时行为一致，固定铜柱可导电但不能推。

本阶段评审重点是“玩家为什么想尝试这一步”：物件外观、卡面与预览提供真实信息，教程只教推车/导电等单条操作，不直接教完整特殊组合。盲测者是否发现巧用需要记录；未发现不等于系统错误，但意味着线索或反馈仍需调整。

## 切片三：双程非对称竞技

范围：A01完整地图、1v1每人两棋、两程角色互换、4轮目标、复归、25秒激活与一次20秒队伍延时。先本地双人或开发房间验证规则，后接网络。两程几何字节应一致，只交换出生及任务配置。

验收门槛：零击倒也可通过护送获胜；原地等待不能凭无限防守拖住一程，4轮后明确比较最高进展与首次到达序号。取得核心、过线、至少一个敌方激活、交付的费用和间隔逐步可见。击倒不加分；复归时只能移动或架盾，不能当路障，形态/药瓶/程次数不会刷新。每一侧分别存在符合4轮规则的无干预交付脚本，再用真实防守测试是否至少有可突破策略。

## 切片四：网络一致性与2v2协作

范围：权威房间、账号最小标识、2v2控制关系、药品/核心交接同意、重连、命令去重、结果账本。不在此阶段引入聊天、公会和交易扩充服务面。

验收矩阵：

| 场景 | 可观察结果 |
|---|---|
| 同一命令重发3次 | 一个扣费事件、一份回执结果、一次结算 |
| 两玩家同时点击各自按钮 | 仅当前激活且有权限的命令可接受 |
| 收药同意时已不相邻/已满包 | 整条交接失败，双方库存与AP不变 |
| 断线20秒后重连 | 补足快照或事件；精力、药品、反应、形态次数不重置 |
| 断线超过60秒 | 一次弃权结算，无重复授奖 |
| 延迟响应晚于超时 | 权威单写者决定唯一顺序，不能既执行攻击又对同一AP架盾 |
| 结果已入账而响应丢失 | 查询或重试返回同一结果，不重复加奖 |
| 客户端快进/关闭特效 | 胜负、时限和逻辑状态保持一致 |

延迟、抖动、断网长度由测试夹具配置并写入报告。以可复现的延迟场景验证，不凭内网手感宣称公网稳定。

## 切片五：首发内容完整接入

范围：10职业、五族、300件装备、P01–P08、A01–A08和相应故事条件全部录入。逐个对象通过内容检查，最终公开卡面与文档逐字段校对。已完成关卡钥匙与工坊解锁永久记账。隐藏大区只作为世界节点与伏笔，不用空战斗地图凑首发数量。

验收门槛：ID清单数量和范围完全匹配；每职业11技（7主动、2被动、2自动）齐备；16图逐张有基准脚本；每件S装备有合法触发例和不触发反例；每件B装备仅属性与所属武器操作生效。对特殊交互选代表性成对/三项组合测试，不声称已穷举300件八槽与技能的全部可能。收集未覆盖组合清单作为风险，优先测循环、转换冲突、计数重置与事件重入。

平衡数据须区分地图、任务侧、1v1/2v2、先手槽、职业、种族和装备，而非只看总胜率。小样本只标为候选问题，参见[数值边界与测试计划](../07_平衡与验收/数值边界与测试计划.md)。若强项来自规则漏洞，先修漏洞；若来自真实取舍，调整机会成本而非禁止跨职。

## 切片六：3D表现与精品体验验收

范围：替换批准的美术、技能演出、音效、镜头和完整营地UI。逻辑事件协议应已经稳定。先完成一族一职业一关的美术切片，审核轮廓、动作、地图可读性和设备帧率，再批量扩充。

验收门槛：关闭特效仍看得清目标格与下一激活；打开特效时命中、护盾、位移、机关变化可以区分；多段动画不会多次扣血。手机小屏和鼠标操作都能先预览再确认，危险操作可在提交前取消。固定镜头中角色不被近景墙长时间遮挡，巨大形态边框准确，核心携带者始终有清晰标记。性能目标按实际最低支持设备记录，未取得设备数据前只能称预算。

## 完成定义、变更和回滚

每项功能完成需要：规则来源明确、正常与失败路径完成、内容卡面一致、回放可复现、必要持久状态可恢复。不可把“模型已导入”“按钮可点”当作机制完成。阶段评审未过时记录阻断问题，不以增加新装备或新画面掩盖。

规则改动先写一条决策记录：发生什么问题、证据回放、改变哪个参数或限制、影响哪些对象、需迁移哪些存档。随后由依赖图确定重跑范围。竞技内容在房间开始锁定，中途不热切。紧急撤回将新匹配指向上一完整内容版本，进行中的合法旧房间继续使用它锁定的版本。

首个可玩版可以缩小内容启用范围，但必须在版本清单明确写“切片”，不能把其缩减当成对本包300件、16图及完整故事需求的替代。最终首发交付仍以上述完整清单和每个条目的验收为准。
