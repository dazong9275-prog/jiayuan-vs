# 命令状态机与确定性结算

本文件将[统一规则](../00_统一规则_先读.md)落实为程序行为。所有结果由战斗内核生成。服务器和离线战役使用同一内核版本，表现层只播放事件。

## 状态与命令封套

BattleState 至少包含 battleId、contentHash、stateRevision、mode、phase、legIndex、roundIndex、activationIndex、activeUnitId、units、board、objects、objectiveState、scheduledEffects、usageCounters、commandReceipts 和随机种子字段。首版命中与暴击不使用随机；如剧情随机对白需要种子，保留在表现层独立流中，不改变规则结果。

```json
{
  "battleId": "battle-example",
  "commandId": "player-generated-unique-id",
  "expectedStateRevision": 42,
  "actorUnitId": "U01",
  "type": "UseSkill",
  "payload": {
    "skillId": "CL03-K01",
    "targetCell": "F4",
    "direction": "East",
    "selectedTargetIds": ["U04"]
  }
}
```

玩家身份来自认证连接，服务端忽略payload中任何伪造owner字段。commandId用于重发去重。服务器按房间单写者顺序处理命令，不允许两个线程同时更改同一房间状态。命令返回accepted、errorCode、newStateRevision、events、stateHash。所有错误至少区分行动者错误、旧状态、目标无效、AP不足、精力不足、冷却中、步行已用、伤害动作已用、沉默阻止、对象固定和落点非法。

逻辑命令类型包括 Move、UseSkill、UseWeaponSignature、BasicAttack、Guard、InteractObject、PickCore、DropCore、HandoffCore、AcceptHandoff、UsePotion、OfferPotion、AcceptPotion、DispelSeal、ResolveOpeningEffect 和 EndActivation。`Guard`固定1AP、0精力，取得8普通盾至下次自身激活开始，每次激活最多一次。不存在独立免费`ChangeFacing`命令；`EndActivation`可附带一次合法四向朝向选择，随后立即结束，不派生装备事件。每种命令明确消耗哪个预算。界面的“选中技能”“拖动箭头”“取消预览”没有提交战斗命令。

## 阶段状态机

```text
Created → ContentLocked → LoadoutLocked → BoardInitialized
  → LegStarted → ActivationStarted → AwaitingCommand
                    ↑                    │
                    │               CommandCommitted
                    │                    ↓
                    │                ResolveEvents
                    │                    ↓
                    │               ObjectiveChecked
                    │                    ↓
                    └─ NextActor ← ActivationEnded
  → LegEnded → IntermissionReset → LegStarted
  → BattleEnded → SettlementPending → SettlementRecorded
```

每次 ResolveEvents 结束后先检查交付是否立即结束当前程，再决定是否返回同一行动者 AwaitingCommand。AP耗尽后只允许提交附带朝向的EndActivation或立即自动结束，不允许独立免费转向反复提交。已明确 EndActivation 则进入下一个单位。轮次结束不是最后一个动画结束，而是本轮已安排的激活槽全部完成或被倒地规则处理。

每程开始重置HP、精力、冷却、消耗品、机关状态和特性程次数；玩家锁定的职业、训练、装备和技能不变。第二程玩家交换实际出生组与任务角色，护送方仍先动；本场护送的地理方向和核心供给/终点坐标保持不变，不额外反转。棋子的 ownerPlayerId 保持本人，scheduler重新建立护送前、截击前、护送后、截击后的逻辑次序。

## 激活开始与冷却

单位维护 `ownActivationSerial`。技能使用时记录 `readyAtOwnActivation = currentSerial + cooldownBlockedActivations + 1`，该值与技能是否曾用过分开保存。CD1在第3次激活使用，则第4次不能用，第5次恢复。倒地后的复归激活仍推进serial，因此冷却照常走。

ActivationStarted按下列固定顺序执行。

1. 推进该单位ownActivationSerial，删除以本激活开始为终点的状态。
2. 若本单位倒地待复归，走复归流程，设置AP1、精力按一般激活开始回2，限制动作为普通移动或架盾，跳过普通起手伤害并消费已到期的伤害预约；倒地已取消原预告，复归不重放。复归期间禁用被动伤害触发。完成后直接进入复归专用AwaitingCommand，不继续执行正常单位的第3–4步。
3. 正常单位回精力2到上限6，获得AP2，清空本次步行与主动伤害标志。
4. 消费本激活到期的延时伤害预约，先占本次主动伤害标志，再处理对应效果。首版每人最多一个未到期预告或其取消后保留的预约。已取消效果不造成伤害，但仍消费本次伤害额度；效果与预约是两个字段，不能删除效果时连带抹掉预约。作用区按原锁定世界格结算。若合法装备（例如S166）允许到期前弃咏，先进入OpeningChoice，由当前行动者提交ResolveOpeningEffect选择正常结算或合法替代；计入本次25秒时限，超时默认正常结算。此窗口不授予普通移动/攻击机会，不打断对手激活。处理完才能进入普通AwaitingCommand。
5. 若到期效果结束战斗或使行动者倒地，直接结束本激活；否则进入 AwaitingCommand。

延时攻击准备命令当场占用主动伤害标志，支付卡片AP/精力并预约下一次自身激活的伤害额度。被移动、沉默、倒地或主动弃咏取消后，保留原费用、冷却及伤害预约至原到期时刻；不得先普攻再准备，也不得取消后改成另一预告绕过次数。

所有perRound计数在整轮开始统一清空，不能在每个角色激活时各清一次。回复上限、反应次数、敌方强移次数、服药次数与物件伤害上限按全局roundIndex引用。状态的到期条件使用明确主体，例如 `EndOfOwnerNextActivation` 或 `EndOfTargetNextActivation`。施术者、持有者和受影响者可能不是同一人。

## 命令执行事务

Preview与Submit共用 `BuildActionPlan`。BuildActionPlan以只读状态为输入，输出消耗、路径、选定目标、命中格、遮挡、防护选择、效果次序和预期状态变化。预览不改变冷却、计数、道具数量或随机序列。

Submit先重新校验revision和所有费用。成功时将ActionPlan一次提交到内部工作状态，执行有界事件队列，最后写入一个新版本。输入失效时整条命令拒绝，AP、药瓶和机关保持原状态。效果中明确允许“推不动但仍命中”的技能，在确认前即把停格纳入计划；不能在扣AP后才发现技能整体目标从未合法。

命令确认后先生成命中区域快照。`HashSet<UnitId>`用于将2×2单位或多格交叠去重，得到一次攻击的受影响单位集合。目标序固定为玩家选定主目标优先、其余按UnitId排序。对于机关位置存在冲突的强移，按该稳定次序处理，后来的对象遇到新占据就停在最后合法格。服务端日志记录停格原因。

## 一次攻击的事件分层

| 阶段 | 处理内容 | 限制 |
|---|---|---|
| CostCommitted | 扣AP/精力、占步行或伤害标志、记录冷却 | 一次提交一次扣费 |
| DefensiveReaction | 按受击者、其队友稳定次序找合法防护反应 | 每棋每轮一次，已消耗即排除；不同护盾按较高有效值 |
| PrimaryDamage | 所有目标按快照算伤害、扣有效盾和HP | 同一技能同UnitId一次；计算使用Int64有理数 |
| ForcedMovement | 处理合法位移并更新占据 | 一目标每轮最多一次敌方强移，至多2格；被固定或0格停留不计成功位移次数 |
| TerrainInteraction | 按明确材质、轨道、机关状态执行 | 一般变形不复制机关身份；非法落点切换拒绝 |
| SecondaryEffect | 装备、反应的附加伤害/治疗/回能 | 每目标物件伤害每轮≤8、治疗≤24、每棋返能≤1；不能再触发装备/反应 |
| DownAndObjective | 倒地、掉核心、占位、过线、交付 | 同次攻击批量扣血后统一决定倒地，不因目标遍历顺序产生额外出手机会 |
| ActivationEnd | 状态到期、面向固化、预告与轮序推进 | 一次主动伤害不会因动画多段重复占用或重复触发 |

事件封套带 originCommandId、rootActionId、sourceUnitId、targetUnitId、stage、isSecondary、sequence。只有白名单Primary事件可进入装备/反应订阅器，Secondary事件只能更新状态与呈现日志。内容中禁止设置递归发起UseSkill的操作。防护反应生成的盾不再触发“获得盾时再反应”。

护盾等值时保留当前已有盾及其原来源/到期时点，避免反复刷同值盾延长持续。新盾严格更高时替换已有盾；受击临时盾只参与本次比较，其余额在该受击事件结束后清除。该等值规则需同时进入玩家卡面说明和战斗测试。

事件总量设一个开发诊断阈值，例如单命令256条。达到阈值时终止工作状态提交、记录规则错误并恢复命令前状态，在正式房间中进入恢复/失败结算流程。不能在正式对局里静默丢掉第257条效果并继续改变公平性。

## 移动、视线和2×2占据

每格用整型坐标x/y，A1映射(0,0)，x向右、y向下。曼哈顿距离为abs(dx)+abs(dy)。逐步移动经过的每一个格都要合法，终点合法不能代替中途校验。普通棋不能穿实心单位；种族动作明确允许的穿越只开放给该次动作。跨障动作仍需验证落点和本次步行额度。

巨化footprint为相对锚格的四个偏移，包含(0,0)。四种2×2朝向由四组固定offset组成，玩家确认前选其中之一。移动时所有占格沿同一方向逐格平移，逐步扫过区域需要合法。锚格保持UnitRuntime唯一定位点；Objective与Interact只查询锚格。命中查询将任一足迹相交转换为一个UnitId。模型可占视觉空间更大，但不得扩大逻辑命中。

地物改变先在候选棋盘模拟所有单位足迹，任何单位落入非法地面则拒绝操作且不扣费。桥到期时若有单位占桥，标记PendingRemoval，等最后一个占据者离开再移除；不得用延迟到期事件循环产生额外资源。形态结束只把footprint缩回锚格，HP和药品次数从runtime保留。所有形态均禁止PickCore、HandoffCore的接收和持有核心；持芯者须先DropCore才可改变形态，已经变形者即使站在核心上也不得拾取。剧情任务物的不同权限由地图明确标记，不能自动套用PvP核心的身份。

视线使用格子射线遍历，固定边界处理。穿恰好两格交点的射线用supercover规则包含两侧碰触格，两侧都被实墙堵住时不可穿角。近战距离与远程视线分别判断；导体折射每段单独求视线和距离，去重目标后再算伤害。

## 物件交互与隐藏构筑

内容只登记“可推”“固定”“导电”“位于轨道”“压力阈值”等事实。推车先查询轨道与固定状态，再位移；电弧查询合法导体、折转次数和每段距离；压力板读有效占据质量。代码中不设 `IsTankMageBuild`、组合名、特定装备清单检测或隐藏职业解锁判断。

如果设计需要一条新物性，先补词典、预览说明和最小反例。例如同样是铜，固定铜柱可导电但不能推，铜箍车二者都能；浅水有步耗但不是深水。局部规则一致才能让玩家从生活观察和战斗回放中自行建立组合。
