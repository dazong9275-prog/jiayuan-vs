# 内容编辑器、编译检查与地图验算

本文件说明如何把 Markdown 规格转成可运行内容，所有阈值引用[统一规则](../00_统一规则_先读.md)。本次只交付设计文件，下面的编辑器和检查器是实施要求，不声称已经实现或跑过对局仿真。

## 一条可追踪的制作流程

策划确认 Markdown → 录入结构化草稿 → 单条校验 → 地图/配装联合校验 → 卡面与棋盘预览 → 人工签核 → 编译不可变内容包 → 开发服白名单 → 回放验证 → 发布。每次修改保留作者、审核者、来源文档、改变字段、内容版本与撤回版本。不能只修改玩家说明而不改运行时参数。

草稿可以保存不完整条目，但必须带 Draft 状态。只有无阻断错误且签核的条目可成为 Approved。引用仍为草稿的技能或地图，不能靠父条目已通过审核绕过发布检查。原型白名单与正式产品清单分开：原型允许只激活若干条目；正式产品必须有 B001–B100、S001–S200、CL01–CL10、R01–R05、P01–P08、A01–A08，不能用占位对象补足计数。

内容包清单写明规则版本、内容哈希、各类对象数、ID集合、引用依赖和迁移表。规范化哈希时固定字段顺序与集合排序，排除编辑器选择状态、导出时间和本机路径；同一规则内容在两台机器应得到同一哈希。

## 编辑器四个工作区

| 工作区 | 编辑内容 | 同屏反馈 |
|---|---|---|
| 对象卡 | 装备、技能、种族、职业专长 | 正预算、费用、持续主体、最终公开卡面、来源链接 |
| 方格地图 | 地面层、物件层、出生层、目标层、表现引用层 | 坐标、占据、视线、关键路径、非法重叠、双方路线 |
| 事件试验台 | 初态、行动者、命令、待结算延时效果 | 支付前后状态、事件阶段、触发/未触发理由、上限扣除 |
| 发布报告 | 依赖树、规则错误、地图警告、差异 | 可定位错误行、阻断原因、最小反例、人工审核记录 |

地图画布不允许用美术模型代替格数据。可关闭所有3D表现，仅看棋盘和ID，仍应能完整判断通路、目标和机关。墙、浅水、低障、可站桥必须使用不同图形和标签；颜色仅是辅助。选择一个装备时可高亮本图可作用的对象；此视图是开发工具，不作为玩家配装推荐或隐藏流派菜单。

## 静态校验清单

| 检查码 | 检查内容 | 失败处理 |
|---|---|---|
| ID001 | 产品ID唯一；所有引用存在；示例ID不能进入产品清单 | 阻断编译，列出来源及引用者 |
| EQ001 | 槽位合法；双手武器占MH/OH；普通装备无额外effect | 阻断；不要自动改槽 |
| EQ002 | 只对正属性算预算，HP/4、武术/1、防抗/2之和≤6；负值不返还预算 | 阻断，展示逐项计算 |
| EQ003 | 禁止直接增加AP、基础移动、精力上限、先手、命中/暴击 | 阻断；条件操作仍需单独批准 |
| SK001 | 每职业11技（7主动、2被动、2自动）且包含规定类型；研习成本仅1或2 | 阻断缺字段或错误成本 |
| SK002 | AP、精力、CD、射程、格形、目标、通道、取值、持续主体齐全 | 阻断，不补猜测默认值 |
| SK003 | 即时范围≤4格；更大范围需预告、锁定格、取消条件和结算时伤害额度 | 阻断；范围按模板格数而非当前站人数量 |
| FX001 | 效果操作与事件阶段在白名单；次级事件禁止重新触发物件/反应 | 阻断任何递归链 |
| FX002 | 沉默只一人一格，无刷新/扩散；形态与药品消耗引用统一计数 | 阻断，不允许特性绕过全局限制 |
| MAP001 | 每坐标显式存在；ASCII与结构化格图一致；出生与实心地物不重合 | 阻断并定位格 |
| MAP002 | 每机关明确初态、触发费用、合法目标、状态转移、复位条件 | 阻断未定义状态与悬空引用 |
| MAP003 | 剧情主线存在无特性装备的证据路线；竞技两侧任务数据齐全 | 缺证据阻断发布 |
| TXT001 | 卡面数字、单位和持续时点来自同一参数；文本键完整 | 阻断缺失关键说明 |
| VIS001 | 所用表现键存在，可用批准的占位表现；未知键不能静默不播放 | 开发版警告，正式版阻断 |

标签须集中登记：标签ID、附着对象类别、生产者、读取操作、到期方式、地图示例。标签可表示物性但不自动赋予额外伤害。一个装备独有的临时对象也须进入该表，并写生命期、是否挡路、双方是否可交互、卸除费用与关末清理规则。

## 自动地图验算的输入与输出

每张地图提交：完整格图、初始物件、开关状态机、玩家出生、敌人及其行为规则、目标条件、基准配置、至少一条可复现基准命令记录。基准配置不得含S装备或要求特定种族跨障；关卡提供的必需操作必须独立于玩家私有配装。验算器运行与游戏相同的 BattleEngine，不能另外写一套“简化机关判定”后宣称能通关。

连通性先分别用1×1、四种锚向2×2足迹生成可达图。1×1必需路线不可依靠巨化；2×2路线可以更窄，需在预览说明实际可达区。A*只证明当时地形可通，不证明机关顺序、敌人阻挡或4轮时限可解。机关状态空间小时枚举全部合法开关状态；较大时以作者脚本加系统性边界组合覆盖，报告实际覆盖量，禁止宣称穷举了所有配装。

每份地图报告至少输出以下内容。

- 初态双方出生至核心、检查区、交付区的最短合法步耗与AP需求；步耗包含浅水和低障规则。
- 基准脚本逐命令通过、实际结束轮次、终点状态、胜利条件、奖励事件。
- 开关操作使脚下失效时的拒绝结果，桥到期被占时的延后移除结果。
- 竞技两套实际起点的首接触激活、无敌方干预的最早交付激活、核心过线后的对方激活间隔。
- 每个复归候选被单独占用、全部占用时的结果；不可因敌方围住出生直接将人塞进墙。
- 高墙穿角、低掩体、折射末段、2×2命中去重、核心锚格计分的反例。

对称性检测可作编辑提醒：比较水平镜像、垂直镜像、180度旋转后的地形、出生与机关；若全部等价则提示违反非对称设计目标。该检查不能证明公平。公平需分别测两侧再交换玩家，原地形保持不变。

## 内容覆盖与同质化报告

装备先按槽位、属性向量、触发、动作、目标、消耗、时机、代价聚合。相同属性向量不是自动违规，但仅改名而上述字段完全相同的特性条目须人工复核。不同条件的“获得6盾”也需看条件是否真的导致不同站位与风险；不能靠数字不同就称新玩法。

建立装备→标签→地图对象的覆盖表。若一件特性在首发所有16图都没有合法作用对象，标红“首发无作用场景”，补地图对象、修改特性或暂不进入首发，不能指望未制作地区补救。地图型装备允许只适用少数图，竞技备战应可查看该地图本来公开的物件规则；不能在开局后才发现装备被模式禁止。

编译报告只证明字段和逻辑约束满足；玩家选择丰富度另用实测检查。默认推荐只给新手稳定基础装备，不能把开发工具发现的强组合直接转成玩家流派按钮。

## 发布门禁与失败例

合并内容前必须没有阻断错误；一般警告逐条有负责人和说明。发布候选固定哈希后，执行全套内容校验、16图基准脚本、代表性规则回放和一次断线结算演练。任何修改规则、数值或格图都生成新哈希并重跑受影响依赖；仅风味文字变化也形成内容版本，但不必重复无依赖的数值仿真。

示例：S装备写“击退后回1精力”，输入目标被墙挡住而实际0格。试验台必须同时显示“攻击成功”“位移未成功”“该返能条件未满足”，不以攻击动画播放推断击退成功。另一例：技能范围十字5格但instant=true，即使测试场只站一敌也应在编译阶段被阻断。
