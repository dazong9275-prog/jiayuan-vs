# 客户端3D表现、战斗界面与内容管线

本文件定义后续制作接口。本轮不生成模型、贴图、动画或Unity场景。美术方向统一为用户狼族参考中的可爱比例、清楚轮廓、具有材质层次的3D兽人；职业外观维持传统识别，跨职玩法从已装备技能与物件操作自然表现。

## 角色、棋盘和表现的三条界线

棋盘内核决定锚格、足迹、逻辑朝向、伤害与物件状态；角色表现决定模型、毛发、布料、武器挂点；界面决定玩家如何读取并提交合法命令。模型变大不自动增加攻击范围，披风遮住一格不等于占据一格。模型、特效或粒子碰撞不得写入HP和通行判定。

角色原型以约2.8–3.2头身作为美术审核范围，头高不计耳尖与角，脚到头顶不计武器。不是每族复制同一张脸：狼保留口鼻与尾部，土拨鼠矮宽且前爪明显，狐耳与尾更蓬松，猫头鹰以面盘和羽翼袖轮廓辨识，黑猪保留鼻盘、短獠牙和厚实躯干。所有成年角色均保持可爱比例与职业重量感，禁止只有狼是可爱形、黑猪回到写实长身材。

以1×1棋格中心对齐角色根节点。普通姿势和静置装备尽量留在格内视觉安全区；长枪、旗帜可伸出但不得遮蔽格边和邻棋关键标记。两种单位交错时，镜头遮挡淡化只改变外观，不改变可见规则数据。

## 角色资源交付契约

| 资源 | 必需内容 | 验收关注 |
|---|---|---|
| 设计参考 | 正、后、左、右及三分之四视角；统一比例尺、服装层级、配色与挂点 | 同一角色结构一致，背部不是正面镜像 |
| 网格 | 闭合主体、分离的可替换装备、正确法线、清楚的实际厚度 | 无纸片身体、无仅正面贴图、无未处理空洞 |
| 材质 | 身体/毛发/布料/金属等批准材质组；共享材质策略 | 侧背纹理完整，缩远仍可识别，不以高光掩盖穿模 |
| 骨骼 | 根、躯干、头、四肢、武器/盾/工具挂点；尾耳羽翼附加链 | 统一命名；种族附加链不改通用动作语义 |
| 动作 | 待机、走、受击、倒地、复归、攻击、咏唱、交互、给药、饮药 | 动作起落稳定；脚不滑；交物清楚 |
| 表现配置 | visualId、挂点名、动画集、材质组、LOD、阴影和特效绑定 | 仅引用资源，不携带战斗数值 |

“人物只有一面”须在资产入口解决：让生成模型AI先接收一致的多视图与背面装备说明，生成完整环绕网格，再作拓扑、法线、UV和骨骼检查。双面材质仅用于设计上薄的叶片、羽毛卡等部位，不能把没有背部几何的身体变成合格模型。验收旋转角色360度，分别看正侧背、俯仰和行走/抬臂姿态；检查腋下、披风内侧、腿间、尾根与武器背侧。自动生成结果必须经这些步骤审核才进入批准库。

给建模AI的工作单应明确：角色ID与批准参考、头身比例、前后不对称附件、闭合体积、材质分区、可替换部位、通用骨架与附加骨链、贴图尺寸预算、输出格式、不可自行改变的轮廓。工作单每次只要求一个角色或一个可替换部件，以多视图一致性审核通过再继续。此为后续制作教程方向，本包不附虚构的已完成模型。

## 技能事件到演出的映射

PresentationDirector订阅已提交事件，按rootActionId组织演出。一次动作可播放预备、释放、飞行、命中、余波，但仅命中事件更新一次显示血量；多段刀光和粒子均为同一伤害结果的表现。每个技能表填出镜头策略、施法动作键、起点挂点、目标挂点、预告模板、冲击特效、声音和是否允许跳过。

| 逻辑事件 | 表现要求 | 不能依赖它发生的事 |
|---|---|---|
| ActionCommitted | 锁定选中、显示已支付费用、开始动作 | 不能等动画回调才扣AP |
| TelegraphPlaced | 地面清楚描边、结算激活提示、危险格列表 | 不能用粒子随机覆盖代替实际范围 |
| PrimaryDamage | 一次清晰命中音、受击方向、数值/护盾变化 | 不可用动画碰撞补第二次伤害 |
| ForcedMovement | 显示实际停格与被挡原因；路径贴合已结算结果 | 动画不能自行绕过实墙 |
| ObjectStateChanged | 阀、桥、轨道车在视觉上对应新状态 | 不能靠门动画中间帧改变通行 |
| ShieldChanged | 区分现有盾、临时受击盾和替换结果 | 同值护盾不能被演出误示为叠加 |
| Downed/Respawned | 明确移出/复归；复归棋淡化并标记限制 | 复归特效不能当遮挡物或攻击判定 |
| ShapeChanged | 足迹先更新预览与边框，模型用短过渡到批准体积 | 不按缩放自动放大攻击或交互距离 |

打击感来自预备与命中的节奏、短促音色、材质响应和可读受击方向。近战命中可有约60–100毫秒视觉停顿与短镜头冲击作为初始调参范围，属于可关闭表现，不暂停服务端计时。小技能演出目标约0.4–0.8秒，大技能约1.0–1.6秒；应在实际设备和玩家测试后调整。这些时长不是规则费用，快速播放不得获得更多AP或额外思考时长。

客户端优先顺序固定为：目标/路径/危险边框最高，核心与单位标识其次，伤害与状态反馈再次，装饰粒子最低。同屏爆发时先减少装饰粒子、透明拖尾和背景闪光，保留真实覆盖边缘。风、水、电可有不同光色，但还须不同纹理与符号；沉默只突出一个受印目标。

## 镜头与点选

战斗默认斜俯视，允许有限旋转和缩放；地图有固定初始镜头。选择技能后显示真实可达区、不可达原因和当前AP/精力预算；选目标后给出伤害、护盾、强移落点、地物变化与已知延时危险。确认前可自由取消，确认后按权威回执更新。

鼠标流程为选棋→选操作→点格预览→确认；手机用相同语义并扩大触区。点到模型与点到地格冲突时显示可选对象列表或重复点选切换，不能随机选到身后棋子。长按只读卡，不自动确认动作。2×2形态明确画锚格、四个占格和可选扩展方向。

镜头自动跟随不能连续抢走玩家正在看的机关。大招首次可轻微拉近，关键路径和剩余计时仍保留；竞技提供固定镜头/减弱震动/快速演出设置，双方规则时钟一致。对战不能用全屏过场隐藏已公开配置或让玩家无法操作。

## 少而清楚的界面层级

营地主页面只放继续故事、地图、队伍、工坊、对战五个入口；红点仅代表真正需要处理的首次奖励/解锁，不堆签到、抽卡、战力弹窗。角色页常驻八项面板：HP、精力、武力、术力、护甲、法抗、移动、武器射程。八个装备槽按人物挂点排列，可用一栏看属性差值、另一栏看物件自身规则。

战斗常驻当前行动者、AP、精力、四棋顺序、轮/程、目标进展和一个操作条。操作条包含步行、普攻、武器招牌、五个自选主动、交互/架盾；主动按主操作栏与展开栏显示，两个自动/两个被动在角色卡查看，不伪装成需要每次点击的主动按钮。上下文动作只在存在合法对象时展开，仍可在详情中查看完整规则。2v2显示队友选择意图与简短标点，不强制打开聊天窗口。

传统职业的新手配装应给出完整且可靠的主流方案，说明武器、护具和技能的直接作用。工坊按器具/槽位和已到地区组织，特殊装备通过实际关卡与锻造线索逐步出现。玩家端不显示“隐藏职业已解锁”“收集这三件成为坦法”等组合提示；一旦玩家获得物件，必须准确显示其真实效果和可用条件。深藏的是组合可能性，不能藏费用、伤害通道和失败原因。

## 场景与关卡内容制作

地图编辑器先批准格图、物件坐标和关卡证据脚本，美术在独立表现层铺地形、河流、山体和建筑。地表能否站立由逻辑格决定；装饰桥若可通行须有对应格和入口，不能只有模型。镜头遮挡区预先标注可淡化对象，首发不用任意多层重叠行走解决构图问题。

每张地图资源清单含：格面套件、机关可视状态、玩家/敌人出生标记、危险地面、核心与交付物、天气、环境音、近景遮挡策略。暴雪不能掩住真实危险格；夜景保留单位轮廓；湖面反光不能覆盖选中边框。世界图的未知大片区域用地貌与航线线索保留探索空间，不让装饰区域错误显示为已可进入关卡。

## 导入、性能预算与验收

资源命名以类别和稳定ID为主，如CHAR_R01、SK_CL07_K01、MAP_P04，显示名可以改。导入流水线检查尺度、朝向、骨骼挂点、材质缺失、纹理路径、动画键、LOD、碰撞代理和资源依赖；错误资源留在草稿库，不被正式配置引用。批准库记录源文件与导出设置，保证模型重新导出后仍能复现。

性能预算先在一张代表性重场景测量：全部英雄、允许的敌人数、最大批准范围特效、夜景或透明水面同时出现。原型以桌面60fps、选定中档手机30fps为目标；最终最低设备、分辨率和画质档在立项验证后锁定，不用泛称“低端机都流畅”。分别记录CPU逻辑、渲染、GPU、内存、纹理和峰值加载，超过预算先找到瓶颈再改LOD/材质/粒子。不能为了帧率删掉逻辑对象或真实预告。

最终视觉验收至少检查：五族同尺度站立与旋转、所有装备挂点及背面、巨化与轻翼、复杂机关变化、4棋互相遮挡、两种输入设备、快速/普通演出同一回放、字幕/色觉/震动选项。每张图保留一个固定相机对照场景，用于后续资源更新后的人工回归。
