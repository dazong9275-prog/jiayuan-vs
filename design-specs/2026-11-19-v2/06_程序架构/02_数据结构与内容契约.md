# 数据结构与内容契约

以[统一规则](../00_统一规则_先读.md)定义的300件装备、10职业、八族和40张地图为产品数据。以下使用 `SCHEMA_` 前缀的对象只展示字段结构，不计入产品数量。内容编译器拒绝 `SCHEMA_` 测例混入正式发布包。

## ID、版本与数值类型

- Product ID 在生命周期内稳定。显示名称可改，存档、存包、回放按ID关联。被移除的内容保留墓碑记录及替换策略。
- `schemaVersion` 表示格式，`contentVersion` 表示数值和规则集合。一次发布以规范化内容生成 SHA-256，组成 `contentHash`。一局开局记录这三个值。
- 生命、精力、AP、伤害、格数和持续计数使用整数。倍率使用有理数分子/分母；运算中用足够宽的有符号整数，最终一次向下取整。不得在客户端用float先乘先取整、服务端用另一种次序。
- 显示文本保留独立本地化键。规则参数与描述模板统一生成关键数值，以防“描述2格、实际3格”。手写风味文字不参与规则。

## 单位与装备快照

| 对象 | 必需字段 | 约束 |
|---|---|---|
| UnitDefinition | id、raceId、classId、visualId | 角色美术ID与职业分开；转换职业不需要新模型ID |
| UnitLoadout | unitId、classId、raceId、training、equipmentSlots、selectedSkills | 主手等8槽恰好有键；允许空值；双手占MH/OH规则在验证时计算 |
| UnitRuntime | unitId、teamId、ownerPlayerId、anchor、facing、footprint、hp、energy、ap、cooldowns、statuses | currentHp与maxHp分离；maxHp来自规则计算；棋盘占据来自footprint，不接受客户端直接填 |
| UsageCounters | round、activation、leg、battle四个周期的计数器 | 所有重置有明确边界；复归只重置规定的局部状态 |
| InventoryEntry | accountId、itemDefinitionId、unlockSource、acquiredAtLedgerId | 同型号固定数值；不保存随机强度词条 |

训练预算先验证10点且单项≤6，再按单位基线加训练和装备，加上按阈值累计的套装属性，最后做各项截断。记录截断前值供调试与配装界面提示，战斗仅取截断后值。研习预算先汇总五个主动、两个自动、两个被动的成本，职业专长和武器招牌不混入这9槽。

## 装备格式示例

```json
{
  "schemaVersion": 1,
  "id": "SCHEMA_EQUIP",
  "displayNameKey": "schema.equip.name",
  "category": "special",
  "slot": "FT",
  "weapon": null,
  "stats": {"hp": 800, "physicalPower": 100, "arcanePower": 100, "armor": 200, "resistance": 200},
  "positiveBudget": 6,
  "effect": {
    "effectId": "SCHEMA_FOOT_EFFECT",
    "trigger": "VoluntaryWalkEnterCell",
    "sourceStage": "Primary",
    "predicates": [
      {"type": "CellTagEquals", "tag": "ShallowWater"},
      {"type": "CounterBelow", "counter": "self.item.waterStep", "period": "Activation", "value": 1}
    ],
    "cost": {"ap": 0, "energy": 0, "charges": 0},
    "operations": [{"type": "IgnoreExtraTerrainStepCost", "amount": 1}],
    "usage": {"counter": "self.item.waterStep", "period": "Activation", "limit": 1},
    "duration": {"kind": "CurrentMovementStep"},
    "secondaryEventsMayTriggerEffects": false
  },
  "acquisition": {"mapId": "P04", "conditionId": "WorkshopPoolUnlocked", "firstCraft": "FreeOnce"},
  "sourceDocument": "SCHEMA_ONLY"
}
```

本例预算为HP800消耗2、武力100消耗1、术力100消耗1、护甲200消耗1、法抗200消耗1。装备特性一次只含一套连贯条件效果；可以由多条操作完成一个明确动作，例如先验证合法格，再移动地物。普通装备的 `effect` 必须为null。未知操作名直接阻断编译，不能静默跳过。

主手武器另填 `weapon.family`、`handedness`、`basicAttack` 和 `signatureSkillId`。普攻基础P1200、AP1、精力0，由武器定义取值通道与合法射程。武器的招牌主动属于武器本身，特性装备额外的一项条件规则需保留独立 `effectId`，以便区分招牌与特效触发。

## 技能格式示例

```json
{
  "schemaVersion": 1,
  "id": "SCHEMA_SKILL",
  "originClassId": "CL03",
  "slotType": "Active",
  "studyCost": 1,
  "requiredWeaponTags": ["Spear"],
  "activationType": "WeaponArt",
  "cost": {"ap": 1, "energy": 1},
  "cooldownBlockedActivations": 1,
  "range": {"minimum": 1, "maximum": 2, "distance": "Manhattan", "lineOfSight": "Direct"},
  "shape": {"type": "ForwardLine", "length": 2, "maximumCells": 2},
  "legalTargets": ["EnemyUnit"],
  "consumesWalk": false,
  "consumesActiveDamage": true,
  "damage": {
    "power": 1200,
    "attackStat": "PhysicalPower",
    "defenseStat": "Armor",
    "channel": "Physical",
    "elementTag": "None",
    "shapeMultiplier": {"numerator": 3, "denominator": 4},
    "penetration": 0
  },
  "delay": null,
  "operations": [],
  "presentationKey": "spear_forward_line"
}
```

技能的攻击属性与伤害通道是两个字段。具备特定转换物件时由统一转换规则得出一次 `ResolvedSkillDefinition`，只允许一个最终攻击属性和一个最终减伤通道。转换在每次主命令预览中选择：最多选一个攻值替换和一个通道替换，且须同时满足各自目标类型与费用。互斥的两个替换不能在同一命令中同时提交，但允许同时装备、在不同场合择一使用；不得仅因背包里有两个转换选项就禁止配装，也不得按装备列表顺序随机决定。

自动技能填 `slotType=Automatic`、`automaticKind`（例如Reaction）、触发阶段、触发对象、费用、有效次数和备战优先级；Reaction不再占独立栏。两个自动技能与装备反应共用每棋每轮一次触发额度，只执行当次优先级最高的合法项。反应若能产生伤害，生成次级事件并消耗此额度。被动填 `slotType=Passive`，永久属性修正与条件操作不能同时伪装成无次数的额外主动。

## 地图格式与出生方案

```json
{
  "schemaVersion": 1,
  "id": "SCHEMA_MAP",
  "mode": "ArenaEscort",
  "size": {"width": 3, "height": 3},
  "coordinateSystem": "A1TopLeft",
  "cells": [
    {"cell": "A1", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "B1", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "C1", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "A2", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "B2", "terrain": "Wall", "height": 1, "tags": ["Solid"]},
    {"cell": "C2", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "A3", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "B3", "terrain": "Ground", "height": 0, "tags": []},
    {"cell": "C3", "terrain": "Ground", "height": 0, "tags": []}
  ],
  "objects": [],
  "spawnGroups": [
    {"id": "West", "unitCells": ["A1", "A3"], "respawnPriority": ["A1", "A3", "B1", "B3"]},
    {"id": "East", "unitCells": ["C1", "C3"], "respawnPriority": ["C1", "C3", "B1", "B3"]}
  ],
  "escortRoutes": [],
  "authoringOnly": true
}
```

这是一份完整3×3格式示例，`authoringOnly=true` 且 `escortRoutes` 为空，因此不可进入竞技白名单。正式竞技图必须提供左右两套路线任务数据，每套含可取核心格、检查区域、合法交付地物、出生组、复归候选优先序、最大4轮规则引用。第二程交换玩家所占出生组与任务角色，地图格图原样保留，不能自动 `x=width-1-x` 镜像几何。

所有格必须显式存在，不用“未填则平地”掩盖漏格。JSON物件层与ASCII文档图必须双向比对。一个格可有地面加不阻挡的压力板，但实墙和可站格不可同时为真。单位起点不能与实心机关重合。暗区/未来地区在世界图使用区域节点，不在当前战斗格里生成不可见敌人。

## 效果标签与字段查错

建立封闭枚举 `TerrainTag`、`MaterialTag`、`ActivationType`、`DamageChannel`、`EventStage`、`DurationKind`。新标签必须在标签词典写出可被哪些操作读取、默认值与反例。材料性质只影响声明的交互；铜导电不会自动附加电伤，水不会自动电死站在上面的人。

公开效果字段需要有可读说明模板。每次编译生成逐物件的最终卡面预览供人工审核，检查持续到谁的下一次激活、对谁有效、是本轮还是本程一次。时间不能写成只有“短暂”“偶尔”“更快”等不可计算词语。

## 最新配置字段补充

`Loadout`固定一个职业专长、一个武器招牌，另有`activeSkillIds[5]`、`passiveSkillIds[2]`、`automaticSkillIds[2]`，自选成本合计≤14，重复技能ID不得占多个槽。`automaticPriority`明确两个自动技能与装备反应候选的触发顺序，所有候选共用每轮一次额度。`GearDefinition.setId`可空；系列、阈值、预算字段见[套装规则](../03_装备/01_系列与套装规则.md)。套装属性只在配置验证时计算，不投递伤害/治疗事件。
